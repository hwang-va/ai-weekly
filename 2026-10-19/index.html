This week

  1. Anthropic · Oct 13, Oct 15 Dev tools

    Anthropic replaced Git and rebuilt code review because agents merge 30,000 changes a day

    Merges to Anthropic's monorepo went from about 2,500 a day in May to over 30,000 in September. A team of seven built Scion (source control) and Antique (code review) in five months, with Claude writing most of the code. Scion assumes "clients are always online", serves about 25 million CI checkouts a day at over 99% cache hits per tier, and runs on a footprint 200x smaller than the old Git mirrors. Two days later the Claude Code team published how it reviews code that Claude writes (about 90% of it): the change, not the author, sets the risk tier; an agent's approval never counts as a person's; and reviews stop after three rounds, because one PR went through more than fifty rounds overnight and 59% of the repeat flags were on code that had been there since the first pass. With the cap, PRs passing after one round went from 65% to 78%. The skeptic note: Rain, who worked on Meta's Mononoke, says Scion's design follows Mononoke without credit; Anthropic's post, updated Oct 15, now names it.

    For us: the week's developer deep item. Copy four things from the checklist: a REVIEW.md per repo, risk tiers set by the change, a round cap, and past incidents as the reviewer's eval set. Then ask where our CI assumes human-rate commits. Catch-up list below.

  3. R Reflection, Meta, DeepSeek · Oct 15 to 17 Models

    Three frontier-size open-weight models ship in three days, under three very different licences

    Update on W41: Reflection's Beam weights are out under Apache 2.0. 501B parameters with 23B active, 1M context, in BF16, FP8 and NVFP4 with a speculative-decoding drafter; SWE-bench Verified 81.6% on Reflection's own card, technical report "coming". Meta's Muse Spark Open (816B, 42B active, text, image, video and audio in) comes under the Muse Model License: products must show "Built with Muse Spark Open", and a licensee with over $20M revenue needs a separate deal to offer it as a service; it needs at least 700 GB of GPU memory. DeepSeek V4.1 Flash 1017 is MIT, 763B, with Terminal-Bench 4.0 up from 31.2 to 42.3 (Opus 5: 51.8), and DeepSeek put a Harness for agent builders in developer preview. Mistral Large 4's weights, promised by the end of October, are still not out.

    For us: Beam is the first with a clean licence for a self-hosted tier, where client data never leaves the VPC. Muse's branding clause rules it out for anything we resell. The catch is hardware: hundreds of gigabytes of GPU memory for each.

  4. Anthropic · Oct 14 to 16 Agents

    The Claude API and Managed Agents now emit OpenTelemetry traces, and Claude Code changed defaults under your scripts

    OpenTelemetry export, in beta, traces Messages API requests, tool uses and Managed Agents sessions into Datadog, Grafana, Langfuse or any OTLP backend. The SDKs emit spans in Python, TypeScript, C#, Go, Java, PHP and Ruby; API-side spans need an admin to add a destination in the Console. Spans carry metadata only by default; prompts and responses are opt-in. Delivery is best effort, so the Usage API stays the record for spend. Claude Code 2.1.299 to 2.1.302: fork subagents are now on by default in claude -p, the Agent SDK, desktop and VS Code (CLAUDE_CODE_FORK_SUBAGENT=0 turns them off); conversations over 200K tokens idle for about 54 minutes get compacted ("idleCompaction": false); tool_decision events now say whether a classifier or a rule decided; --sandbox on claude remote-control is now an error. Same week: Opus 5.5 fast mode left research preview and no longer needs a beta header.

    For us: one trace from our harness through the API, without our own logging code. Keep it on metadata only until we decide where prompt content may be stored. Check every scheduled claude -p job before fork subagents change what it does.

  5. OpenCode, OpenAI Codex · Oct 17, trending since Sep 25 Security

    Coding-agent tools became the target: OpenCode lost users' AI keys, and Codex runs a self-updating daemon

    OpenCode found unauthorised access to a legacy system it was retiring and told users that "third party provider keys (eg OpenAI, Anthropic) saved in your workspace may have been exposed". About 1.4% of users of its hosted Console were affected, not the local CLI; users report unauthorised charges and were told to revoke and replace their keys. News report of OpenCode's post and email; no written incident report yet. Separately, a GitHub issue open since Sep 25, and argued over this week, shows that since Codex CLI 0.157.0 an interactive session starts a background server that outlives every window, copies about 374 MB, and runs an hourly self-updater that can interrupt a turn. No OpenAI reply on the issue yet; users report codex features disable daemon_auto_start turns it off.

    For us: keep provider keys out of hosted dashboards: one key per tool, a spending cap on each, and rotation. List what each coding agent we approve installs, keeps running and updates on a developer machine.

The trend

Tools built for people broke at agent scale, and the controls moved outside the model.

Git broke at 30,000 merges a day, so Anthropic replaced it. Code review broke at fifty rounds a night, so it got risk tiers and a cap. Logs became OpenTelemetry traces. Keys stored in one hosted dashboard became one breach. At AI Engineer New York, OpenAI, Anthropic, Two Sigma and Bloomberg described the same answer for finance: a scoped identity, an approval before the agent acts, an audit trail, a budget and a kill switch, all of it "deterministic controls outside the model". Bloomberg ships it as a product, with entitlements checked on every MCP call. For a fintech harness the work this quarter is the layer around the model, not the model.
